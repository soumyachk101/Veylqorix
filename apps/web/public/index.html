What it verifies

A unified security workflow that runs the checks that actually matter, reports their real results, and blocks when the policy says it should.

Dependency security

Known-CVE auditing for Node, Python, and more, with severity, affected versions, and patched targets — distinguishing security updates from breaking ones.

Secret detection

Accidentally committed keys, tokens, and private keys are detected and redacted in every output. We never print a full secret.

Static analysis

Language-appropriate linters and security rules (Clippy, ESLint, Ruff, Bandit, Semgrep when configured) run only where they apply.

Quality gate

Configurable severities and strictness. A scanner that errors or a skipped mandatory check degrades coverage — it is never quietly treated as a pass.

Actionable reports

Every finding carries a file, line, confidence, and remediation. Reports export to JSON, Markdown, and SARIF.

Verify the fix

Rerun the specific check that found the issue and confirm it is resolved — a fix is not claimed until a fresh run proves it.

The security gate, honestly

Deterministic exit codes

  • 0 PASS — clean and full coverage
  • 1 FAIL — a blocking finding
  • 2 INCOMPLETE — coverage degraded, never a green pass

A scanner that errors or a mandatory check that is skipped degrades coverage to INCOMPLETE. Incomplete is never equal to pass.

Branch protection is the boundary

The workflow does not block merges by itself. It enforces only when your repo requires its status check via branch protection or a ruleset. Until that is configured, the gate is advisory — and Veylqorix says so, plainly.
